# Grok Build 1.0.13 parity ledger

## Scope

The published client behavior is **integrated and locally validated**, subject
to the explicit platform and unpublished-service limits below.
The starting fork is `35e1a04f303ed6a98f60fea9df263b3a062e3456`; the pinned
upstream target is `bb7f39d5858cbf5e00de639367f59debbdcb0138` (2026-08-31,
Grok Build `1.0.13`). The histories have no merge base. Changes are replayed
by behavior while retaining Open Grok's providers, Code Mode, session bus,
experience memory, sandbox defaults, namespaced state, and release system.

The last documented upstream import, `19d42e35` / `1.0.6`, was selective.
Previously omitted behavior was included in the review. The intervening
snapshots are `07b2f714`, `c2ad97f8`, `77cd7eb6`, `9684fa3c`, and `bc7f02ed`.
The final snapshot's behavior takes precedence over superseded intermediate
defaults. Comment removal, test deletion, and internal crate moves alone are
not feature requirements.

## Compatibility decisions

- The default `clone` backend uses Git, as requested. `--grove` is optional;
  its protocol is based on the official 1.0.13 client, not guessed request
  fields. No live Grove daemon or mount was available for verification.
- The published target contains disabled app-builder/deploy placeholders,
  not the implementation or a callable service. Preserve that disabled
  surface; do not claim to implement an unpublished backend.
- The single-file-folder ZIP release-note change has no corresponding
  implementation in the published Rust snapshot. It remains an external
  service limitation, not a locally verified feature.
- The generic `xai-message-delivery-core` envelope extraction is omitted:
  the fork has a single immutable delivery payload and typed model-authored
  input authority rather than independently supplied identities. An audit
  found and fixed its one behavioral difference: non-Queue active-parent
  operations are rejected before dispatch and again before actor admission.
  Native/team/session-bus control routes retain their existing semantics.
- Dashboard persistence follows the target's opt-in behavior. Its store has
  grouping/rank and cross-connection APIs, but the target does not provide
  automatic live cross-process polling or interactive unloaded-session rows.

- Existing disabled cumulative session/memory exports stay disabled. Permission
  telemetry adds closed, content-free fields without widening external OTEL
  projections or provider export gates.
- Deployment-key staging retains stricter identity binding: offline replacement
  needs an authenticated prior deployment identity and a fresh signed policy.
  Unknown or changed bindings require online repair.

### Platform and service limits

- Five unchanged shell PTY tests cannot open a pseudo-terminal in this host
  sandbox (`openpty: EPERM`). PTY targets compile, but live mode-switch,
  external-editor and terminal compositor validation is not claimed.
- Two unchanged HEIC fixtures require macOS `sips` encoding, which fails here.
  Their conversion paths are not declared verified by other image tests.
- One unchanged workspace process-reaping test uses `ps` as its oracle;
  this sandbox denies `ps`. It is explicitly excluded, not weakened.
- `version --json` reaches application sandbox initialization and correctly
  refuses to run when nested initialization is denied. No protection was
  disabled to force a passing smoke.
- Windows/Linux-specific runtime behavior and live Grove/NFS mounts were not
  exercised on this macOS host. Unpublished services remain the compatibility
  limits listed above, not service-availability claims.

### Preserved fork contracts

Open Grok namespaced state, metadata-selected provider identity, explicit-key
precedence, provider-local credentials/catalogs/opaque histories/hosted tools,
and the monotonic export boundary remain. Native Codex, persistent Code Mode
with hidden transport cards, flat/native teams, detached swarms, session bus,
goals and experience memory remain.

The actor stays on its LocalSet. Finalization binds prompt id, turn epoch and
task identity, retaining durable acknowledgement ordering and stale-completion
guards. Model-authored parent/team/bus messages never become human consent.
Workspace confinement stays fail-closed; plan edit gates run before hooks and
after rewritten input, and hook Allow never skips later permission checks.

Migration validation did not publish release assets or replace an installed
binary. Release/version publication is handled separately.
