# Upstream 1.0.13 implementation ownership

The user explicitly requested parallel agents for the full-parity migration.
All slices use upstream `bb7f39d5`, with `19d42e35` as a comparison snapshot,
and the fork at `35e1a04f` as the preservation baseline. These are Rust-only
slices; Swift targets are not applicable.

Reference trees are read-only inputs under
`/tmp/opengrok-upstream-replay/{base,target,fork}`. No Git merge, new branch,
commit, push, release, or installed-binary replacement is authorized.

## Shared rules

- Paths below are relative to `crates/codegen/` unless otherwise specified.
- Lead-reserved files override every directory assignment. Ask the lead before
  editing outside an assignment; send exact integration diffs instead.
- Preserve fork functionality and tests. Do not copy wholesale upstream
  comment/test deletions or mechanically replace diverged files.
- Use attributed `apply_patch` edits. Do not alter root `Cargo.toml` or
  `Cargo.lock`; report dependency requirements to the lead.
- Only the lead runs Cargo commands while the baseline/integration build owns
  the shared build directory. Workers may perform scoped rustfmt checks with
  the pinned toolchain and report requested test commands.
- Hand off owned files, behavior changes, source provenance, tests, required
  shared-file glue, and any unimplemented feature explicitly.

  `session/acp_session/hooks.rs`, plus `acp_session_impl/hook_dispatch.rs` and
