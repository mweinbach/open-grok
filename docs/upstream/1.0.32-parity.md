## Compatibility decisions

- Memory v2 is isolated at `$OPENGROK_HOME/memory-v2/` and never reads or
  writes the legacy `$OPENGROK_HOME/memory/` tree or experience index.
- Enablement stays opt-in. `[memory] enabled = true` keeps the legacy +
  experience pipeline. `[memory_v2] enabled = true` selects v2. CLI/env
  `GROK_MEMORY=0` / `--no-memory` still disable both.
- Remote xAI `memory_v2` feature flags are accepted but cannot override a
  local opt-out. Open Grok does not default-on via unpublished remote gates.
- Workspace hashes for v2 reuse the fork's host-aware identity so GitHub and
  GitLab clones of the same name do not share memory.
- `xai-grok-login` extraction, diagnostic OTEL upload, Grove-only protocol
  guesswork, and unpublished app-builder/deploy surfaces stay omitted.
- 1.0.33/1.0.34 changelog items without published source stay deferred.

## Imported so far

- Isolated Memory v2 crate, config overlay, spawn/file-tool wiring. Opt-in
  via `[memory_v2] enabled = true`. Experience memory and
  `$OPENGROK_HOME/memory/` stay untouched.
- Blocking wait ceiling is 1 hour (`3_600_000` ms), advertised as
  `{max_wait_ms}`. Hosts still override with `OPENGROK_MAX_WAIT_BLOCK_MS`.
- Auto-mode `git` no longer rides prefix allowlists. Path-mode discards
  (`git checkout --`, `git checkout -- file`) fail closed; branch switches
  (`git checkout main`) stay routine. Env remains `OPENGROK_*`, not
  `GROK_*`.
