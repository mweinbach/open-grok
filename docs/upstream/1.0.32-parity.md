## Compatibility decisions

- Memory v2 is isolated at `$OPENGROK_HOME/memory-v2/` and never reads or
  writes the legacy `$OPENGROK_HOME/memory/` tree or experience index.
- Enablement stays opt-in. `[memory] enabled = true` keeps the legacy +
  experience pipeline. `[memory_v2] enabled = true` selects v2. CLI/env
  `GROK_MEMORY=0` / `--no-memory` still disable both.
- Remote xAI `memory_v2` feature flags are accepted but cannot override a
  local opt-out. Open Grok does not default-on via unpublished remote gates.
- Workspace hashes for v2 reuse the fork's host-aware identity so GitHub and
  GitLab clones of the same name do not share memory.
- `xai-grok-login` extraction, diagnostic OTEL upload, Grove-only protocol
  guesswork, and unpublished app-builder/deploy surfaces stay omitted.
- 1.0.33/1.0.34 changelog items without published source stay deferred.

## Imported so far

- Isolated Memory v2 crate, config overlay, spawn/file-tool wiring. Opt-in
  via `[memory_v2] enabled = true`. Experience memory and
  `$OPENGROK_HOME/memory/` stay untouched.
- Memory v2 session runtime: end-turn capture, `/flush` barrier, `/dream`,
  `/memory status`, `x.ai/memory/forget`, and first-turn v2 manifest
  injection. Capture and Dream route through
  `prepare_auxiliary_sampling(AuxiliaryModelPurpose::Memory)` and never
  inherit the chat provider. V2 mode never runs experience hooks. Durable
  transcript reads enforce byte/item caps.
- Blocking wait ceiling is 1 hour (`3_600_000` ms), advertised as
  `{max_wait_ms}`. Hosts still override with `OPENGROK_MAX_WAIT_BLOCK_MS`.
- Auto-mode `git` no longer rides prefix allowlists. Path-mode discards
  (`git checkout --`, `git checkout -- file`) fail closed; branch switches
  (`git checkout main`) stay routine. Env remains `OPENGROK_*`, not
  `GROK_*`.
- MCP catalog keys (`server__tool`) admit up to 256 chars; the 64-char
  cap stays for provider function names (`search_tool` / `use_tool`).
  `structuredContent` is appended to local and gateway MCP results when
  it is not already inlined.
- Mid-message `/btw` hoists: `explain. /btw what is X` becomes
  `/btw explain. what is X` and still bypasses the prompt queue.
- Mid-turn `Esc` never cancels. It toasts (or writes one minimal system
  line) `Press Ctrl+c to cancel the turn`. `Ctrl+C` on an empty prompt
  remains the cancel gesture. A cancelling turn swallows Esc silently.
- Feedback draft ACP: `x.ai/feedback/drafts/{list,get,update,delete}`
  over `FeedbackDraftStore` in the session directory.
- Feedback modal UI: `/feedback` opens the taxonomy modal (Write /
  Drafts tabs) instead of the freeform pane. Immediate and modal
  submits post `ClientFeedbackInput` with structured metadata. Image
  attachments stay refused on non-xAI sessions. Thank-you copy is
  Open Grok branded.
- Send-from-draft: a loaded Drafts-tab send POSTs
  `FeedbackDraftSendRequest` (edited body + taxonomy). The shell
  rejects legacy fields on that shape, deletes the draft after a
  successful submit, and maps a timeout-like proxy failure to
  `OutcomeUnknown` so the modal can keep the draft. In-modal trace
  step and `x.ai/feedback/upload-trace` stay omitted.
- `send_feedback` tool: parent Grok Build sessions advertise a local
  draft writer (`ToolKind::Feedback`). It appends or updates
  `feedback_drafts.json` via `FeedbackDraftStore` and never posts
  network feedback. Description copy is Open Grok branded. Subagents
  and non-parent toolsets do not see the tool. Permissions map it to
  `AccessKind::Read(None)` because this tree has no `AccessKind::Tool`
  yet; remapping Task/ApplyPatch stays deferred. The description
  renderer now carries `feedback_drafts_path`.
- MCP 2026-07-28 mid-call elicitation (MRTR): `rmcp` is pinned at
  `=3.2.0` (reqwest 0.13 stays quarantined). HTTP/ACP handshakes
  probe `server/discover` preferring `2026-07-28`, then fall back to
  `initialize` pinned at `2025-11-25`. Stdio stays initialize-only.
  Interactive `inputRequests` loop through form/URL elicitation up to
  `DEFAULT_MRTR_MAX_ROUNDS`; `requestState`-only rounds poll 250ms
  doubling to 5s for up to 600s. Every MRTR round keeps
  `McpCallMetadata` on `params.meta`. Cancel-on-drop sends
  `notifications/cancelled`. Fork user-agent stays `open-grok/{version}`.
  `AccessKind::Tool` and `x.ai/feedback/upload-trace` stay omitted.
- Subagent `send_subagent_message` delivery: closed snake_case
  `steer` / `queue` / `interject`. Omitted `delivery` defaults to
  `steer`; the hidden legacy `queue` flag still maps to queue when
  `delivery` is absent. Child runtime and parent admission forward
  all three operations through the existing `pending_inputs` path.
  Pager cards read `Message sent to` / `queued for` / `interjected to`.
  `try_new` still defaults to Queue for non-tool callers. Blocking-wait
  interrupt, continue-after-finish, and `xai-message-delivery-core`
  stay omitted so Interject does not double-deliver through
  `pending_interjections`.
