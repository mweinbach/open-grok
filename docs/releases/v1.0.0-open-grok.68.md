# Open Grok v1.0.0-open-grok.68

This release makes failed Codex `apply_patch` edits visible to the model in
Code Mode, and names the exact lines that did not match.

## Code Mode apply_patch failures reach the model

- Nested `apply_patch` is not written into model history. Successful patches
  still resolve to `{}` (the filesystem change is the result).
- Failed patches (`ApplicationError`, `ParseError`, `EmptyPatch`) now reject
  `await tools.apply_patch(...)` after the TUI card is emitted, so the exec
  cell fails with the patcher's diagnostic instead of looking like a
  successful no-op.
- Session events now record those nested calls as errors.

## Patch errors name the lines that did not match

- Missing-hunk failures still start with the Codex-format prefix and the
  closest file region (line numbers and similarity).
- They now also list each mismatched line as `expected:` vs `actual:`, and
  label whitespace-only misses. Exact matches in that window are omitted.

## Compatibility guarantees

- Keeps Open Grok state isolated under `$OPENGROK_HOME`, `~/.opengrok`, and project `.opengrok/` paths.
- Preserves independent credentials, catalogs, hosted tools, and export boundaries for every supported provider.
- Retains Open Grok branding and Code Mode transport behavior throughout.

## Install

```sh
curl -fsSL https://github.com/mweinbach/open-grok/releases/latest/download/install.sh | bash

```
